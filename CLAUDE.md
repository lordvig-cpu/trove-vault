# TroveVault: project conventions

A universal collections app (Next.js 16, React, Tailwind 4, Supabase). Users define collections of
items, and design their own item templates in a visual layout builder. Read `AGENTS.md` (imported
above) before writing Next.js code; do not edit it, `next dev` regenerates it.

## Running and checking

- Dev server: `npm run dev` (port 3000). Type check: `npx tsc --noEmit`. Lint: `npm run lint`
  (there are known pre-existing lint errors; do not add new ones).
- Tests: `npm run build` first, then `npm test`. Playwright runs against a production build on port
  3100 using the Edge channel. Some tests are `test.fixme` because they need seeded data.
- For any UI change, look at it in the browser (Playwright with `channel: 'msedge'` against the dev
  server) before calling it done. For refactors, compare before/after screenshots and computed styles.
- Never commit `next-env.d.ts` (generated). Use conventional commit messages (`feat:`, `fix:`,
  `refactor:`, `chore:`, `test:`) and small, focused commits.
- Line endings are LF everywhere (`.gitattributes`, `.editorconfig`).

## Code conventions

- **Naming:** the shared tree-view UI is called "Tree" (`TreeActionMenu`, `useTreeActionMenu`,
  `tree-*` CSS classes, `--tree-*` theme variables). The old "Explorer" name is gone; do not
  reintroduce it. The Items panel's dock id is `'items'`.
- **Icons:** SVG components in `components/icons/`, not emoji or unicode symbols. (Some emoji remain
  and are being replaced over time.)
- **Colors:** use theme CSS variables, never hard-coded colors. `--primary-accent` is the blue,
  `--secondary-accent` is the amber. Themes live in `app/styles/themes/`; the OKLCH recipe is
  generated by `scripts/generate-oklch-theme.mjs`, so change the generator as well as the CSS.
- **Tailwind:** class names must appear as full literal strings; never build them with `${}`
  interpolation (Tailwind cannot see them). Shared editor-bar styles are in
  `components/editorBarStyles.ts`.
- **Styling states:** controls are amber by default, white on hover, light blue when they represent a
  selected/set value; destructive hover uses the `--tree-menu-danger-*` variables.

## Template editor

- Every container is a Row or a Column (`resolveDirection` in `types/layout.ts`); new containers start
  with the opposite of their parent's direction.
- Templates are fluid. Preview width and zoom are editor-only state (`CanvasZoomContext`), reset to
  Fit / 100% when the editor closes. Container sizing (Width, Min/Max, Height, stack-below) is stored
  on the container; drag handles only appear on Custom containers.
- The editor bar (tools, preview width, zoom) is rendered by `TemplateEditorBar` into the slot under
  the header (`#template-toolbar-slot`).
- Edit Template does not auto-open the side panels (`AUTO_OPEN_TEMPLATE_PANELS` in `app/page.tsx`).
- Layout persistence: localStorage on every change, plus a debounced Supabase write. The
  `layout_config` column is not in `.supabase/schema.sql` yet, so remote saves currently fail (with
  one console warning per session).

## Known state

- No authentication yet. The Row Level Security policies in `.supabase/schema.sql` are open
  development policies (public read/write); they must be replaced when accounts are added.
- The app is designed for wide desktop screens. Template building is not planned for phones.
